Choosing a model

The arithmetic of what fits, what the tags mean, and what the conversation costs on top.

Checked 26 Oct 2026 · figures from a 24 GB Apple Silicon Mac

The arithmetic

weights  ≈  parameters (billions) × 0.7 GB        # at the usual ~4-bit quantization
budget   =  total RAM − what the OS needs (~5 GB on a Mac)
fits if:    weights ≤ 0.6 × total RAM             # the rest is context + headroom

Checked here: qwen3.5:9b is 9.7B parameters and 7.6 GB on disk — 0.78 GB per billion.

Reading a quantization tag

Q4~4 bits per weight. Q2–Q8 exist; lower is smaller and worse.
_Kk-quant: spends more bits on the layers that need them. Beats the older flat methods at equal size.
_S / _M / _LSmall, medium, large within the family.
nvfp4, mxfp4Newer 4-bit float formats. Not GGUF k-quants — the size arithmetic still holds. qwen3.5:9b is nvfp4.

What the conversation costs

The KV cache grows with the context you actually use. Measured here with qwen3.5:9b:

Context in useSIZE in ollama ps
~50 tokens7.7 GB
7,250 tokens9.1 GB
48,050 tokens11 GB

Default context by VRAM: <24 GiB → 4k, 24–48 GiB → 32k, ≥48 GiB → 256k. Raise with OLLAMA_CONTEXT_LENGTH=64000 ollama serve; agents and coding tools want ≥64k.

Commands

CommandTells you
ollama show <model>Parameters, quantization, advertised context length, capabilities.
ollama listOn-disk size of what you have pulled.
ollama psLive footprint, GPU/CPU split, allocated context.
ollama stop <model>— frees the memory immediately.

Advertised ≠ allocated. ollama show reports what the model supports; ollama ps reports what it was given. Measured here: 262,144 advertised, 4,096 allocated. Always check the second one.

Memory you can buy back

SettingEffect
OLLAMA_FLASH_ATTENTION=1Significantly reduces memory as context grows. Automatic where supported.
OLLAMA_KV_CACHE_TYPEQuantizes the conversation cache (default f16). Needs flash attention. Global — affects every model.
Lower num_ctxThe bluntest and most reliable saving.

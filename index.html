Learning local LLMs, one small thing at a time

Ollama Bootcamp

Nine lessons on running local models well and making their output safe to use in code. Every figure in them was measured on this machine, not quoted from a blog post.

9 lessons · 5 reference sheets · last updated 26 Oct 2026

Each lesson is one idea in 10–15 minutes, with a Part 1 that stands on its own — plain language, one command, a short quiz — and a Part 2 with the measurements and edge cases for when you want them. Start at the top and go in order; the lessons interleave two tracks deliberately, because switching subjects helps things stick.

The lessons

In order

01

The grammar, not the promptOutput

Passing a schema does not ask the model for JSON — it makes every other shape unsamplable. What that guarantees, and the three things it leaves entirely to you.

02

Reading the machineOperations

A model reads fast and writes slowly, and almost every "why is this slow" question is about which one. The timing receipt, ollama ps, and what a long conversation really costs.

03

When the model can't complyOutput

A reply that stops halfway is valid JSON right up to where it stops. Detecting it with done_reason, and building a retry loop that gives up for a reason.

04

Fitting a model in your memoryOperations

Choosing a model is arithmetic: parameters, bits, and what the conversation needs on top. Read any tag and know whether it will run before you download it.

05

Schemas a small model can fillOutput

The same request in three shapes: 290 tokens, 332 tokens, or a failure. Schema design turns out to be a latency and reliability decision.

06

Does a bigger context make it dumber?Operations

The lesson with an honest "I don't know" in it. A documented effect, a flaw in this course's own earlier experiment, and how to run a version you can trust.

07

What to verify, what to re-askOutput

Three buckets for every error: code fixes it, the model fixes it, nobody fixes it. Loops that converge, and knowing when yours will not.

08

Staying fast in something realOperations

What changes when the model sits behind an application: streaming, warm-up, cancellation, and what happens when two people ask at once.

09

Designing an exercise from a findingPortfolio

The payoff: turning one measured surprise into an exercise with a lesson, tests and honest caveats. Worked through end to end for exercise 02.

How this course works

  • Everything is measured, and says so. Figures come with the machine, model and date they were taken on. Where a claim is folklore, it is labelled folklore.
  • Mistakes stay visible. Lesson 06 opens by picking apart a flawed experiment from Lesson 02. Corrections are more instructive than a clean record.
  • Null results count. "No effect at 8k tokens" is written down, because almost nobody writes that down.
  • Every lesson ends by inviting questions. The quizzes are retrieval practice — getting one wrong is the useful outcome, not a problem.

Context for all of this: MISSION.md (why this is being learned), RESOURCES.md (the trusted sources, and the gaps), and docs/ollama-basics.md (the primer that came before the lessons).

Glossary

The vocabulary this course uses, in the sense it uses it. Where the field has several words for one thing, the preferred one is given and the rest listed as aliases.

Updated 26 Oct 2026

Running a model

tokenA chunk of text, roughly ¾ of a word. The unit models count in. Avoid: word, character.
prefillThe phase where the model reads the prompt. Parallel, so fast. Aliases: prompt eval, prompt processing.
decodeThe phase where the model writes the reply, one token at a time. Aliases: eval, generation.
context windowThe maximum tokens a model can hold at once. Note the split: advertised (what the model supports, from ollama show) vs allocated (what Ollama gave it, from ollama ps).
KV cacheThe model's stored representation of text it has already read, so an unchanged prefix need not be re-read. Lives in RAM; grows with context.
cold startThe delay while weights load from disk into memory. Appears as load_duration. Models unload after 5 minutes idle by default.
spillWhen a model does not fit in memory and part of it runs on the CPU, roughly 10× slower. Visible as a non-100% GPU value under PROCESSOR. Aliases: offload, CPU offloading.
quantizationStoring each weight in fewer bits — lossy compression for model weights. ~4 bits is the usual default.
k-quantA quantization method that spends more bits on layers that need them. The K in Q4_K_M.
runnerThe engine actually executing the model under Ollama — mlx on Apple Silicon here, llama.cpp elsewhere. Behaviour can differ between them.
keep-aliveHow long a model stays resident after a request. Default 5 minutes; -1 pins it, 0 unloads immediately.

Getting structure out

constrained decodingRestricting which tokens may be sampled so output must match a grammar. What format does. Avoid: "JSON mode" for this — that is the weaker string option.
GBNFThe grammar format llama.cpp uses. Your JSON schema is compiled into one.
logit maskingThe mechanism: tokens that would break the grammar are forbidden before sampling picks one.
schemaThe declared shape of a reply. Here, a Zod object converted with z.toJSONSchema() and used both to constrain generation and to parse the result.
truncationGeneration stopping before the structure is closed, usually at num_predict. Produces valid-so-far, unparseable JSON. Detect with done_reason === "length".
verificationCode checking whether a syntactically valid reply is actually correct. The grammar cannot do this; it is the half left to you.
the seamThis course's term for the division of labour: the model supplies judgement, code supplies determinism. Every exercise is built on it.

Measuring

time to first tokenWhat a user actually feels. Load time plus prefill. Streaming makes this the number that matters instead of total time.
decode rateeval_count / eval_duration × 10⁹. The figure people mean by "tokens per second". ~50/s here.
prefill rateThe same arithmetic on the prompt_eval_* pair. ~120/s fresh, ~881/s when the prefix is cached.
needle testHiding one fact in a long prompt and asking for it back, varying the depth, to test long-context retrieval.
null resultAn experiment that found no effect. A finding worth writing down, not a failed run.

Ambiguities resolved for this course. "Context" always means the allocated window unless stated otherwise. "Tokens per second" is never used without saying prefill or decode. "JSON mode" means format: "json"; passing a schema is called constrained decoding.
